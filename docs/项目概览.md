# 项目概览

## 目标

Daily Global Briefing 是一个采用 MIT 许可证的中文全球晨报系统。它将分散在公开来源中的候选信息，转化为一封适合手机阅读、保留来源依据且有明确分析边界的每日简报。你可以 Fork 仓库，在自己的 GitHub Actions、模型服务和邮件账户中独立部署。

系统优先处理人工智能、数字经济、中国经济与政策、全球经济与政治，以及具有实际技术价值的开源生态变化。它追求低噪声和可核查，不把新闻数量或全量抓取当作目标。

## 工作方式

```text
来源注册表
  ↓
候选发现与覆盖审计
  ↓
正文提取、公开访问检查与发布时间识别
  ↓
主题路由、硬性排除、事件合并与历史去重
  ↓
结构化中文成稿
  ↓
独立复核与确定性校验
  ↓
HTML、纯文本和 MIME 邮件产物
```

内容窗口按北京时间固定计算为前一日 07:00 至当日 07:00。每一条进入成稿的关键事实都需要关联到具体公开来源；无法确认、只依赖付费墙或与来源冲突的内容会被拒绝。

## 质量控制

| 环节 | 机制 |
| --- | --- |
| 来源 | 来源注册表、域名白名单、来源覆盖组与公开访问检查 |
| 时间 | 固定二十四小时窗口、发布日期提取与窗口外过滤 |
| 内容 | 主题相关性、硬性排除规则、事件指纹和中文标题相似度去重 |
| 事实 | 关键事实与来源链接绑定；模型生成后独立复核 |
| 运行 | 月度成本门禁、运行锁、最小状态记录与重复投递保护 |

自动采集只负责发现，不能直接决定刊登。最终成稿还需要通过正文可读性、证据、去重、复核和规则校验。

## 输出与阅读体验

每次运行可生成以下本地产物：

- 移动端优先的 HTML 邮件正文
- 同封邮件的纯文本备用正文
- 标准 MIME 邮件文件
- 入选事件的最小审计数据与拒绝原因摘要

邮件渲染以 iPhone Gmail 的单栏阅读为优先目标，并兼顾浅色与深色模式。输出目录、抓取缓存和运行状态均是可重新生成的本地数据，不纳入 Git。

## 运行方式

项目既可以通过本地命令运行样例，也可以通过 GitHub Actions 执行日内巡检、每日正式生成和周度商业案例。巡检只发现与检查来源；只有正式任务才会进行成稿和复核。

发送邮件是一个明确的可选步骤：需要同时满足运行参数和环境开关，任何一个条件缺失时，系统只生成本地邮件产物。密钥和个人投递地址只应配置在受保护的本机环境或云端密钥管理器中。

## 已知边界

- 公开网站可能调整页面、限制自动访问或延迟更新，单一来源不可视为长期稳定。
- 结构化生成和复核能降低错误风险，但不能替代对重大事件的人工判断。
- 有限的来源集合不能保证不遗漏所有重要信息；系统通过多源覆盖、巡检和审计降低遗漏概率。
- 本项目不以收件箱、邮件回复或联系人数据作为输入。
