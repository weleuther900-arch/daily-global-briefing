# 内容规范 v2：实施与验收

## 复核后的内容边界

新模型、新应用、新工具和新玩法是优先发现方向；日常聚焦科技与数字商业，宏观政治只作为相关背景。内容还包括公司经营、财报、竞争、产业趋势、重要商业政策、可核实的新用法和有解释价值的深度材料。不是只有产品发布才有内容，也不因某天消息少而降低证据标准或凑固定条数。

产品满足明显关注度或可信实际使用反馈之一即可进入评估；演示、邀请测试、等待名单均可介绍，但必须交代开放状态。区分作者/厂商声明、实际使用反馈与独立验证。热度不等于质量，财报或制度变化不需要伪造热度才能入选。

背景补充不设年代上限。保留原始日期，说明今天阅读的价值、可能过时之处，检查长期已刊记录。新动态、关注度观察、背景补充不能混用时间口径。同一产品的新事实可以再讲，旧事实换标题不能再算新内容。

## 呈现与内容供给

少数重要事件重点展开，其他通过证据审校的内容用短消息保留。短消息包含变化、意义、证据边界及来源，不机械要求两个长稿小节。重点稿进一步解释机制、差异和适用条件。没有任何栏目的固定最低条数，也不沿用每栏四条的内容上限。

有限运行时间和预算仍是实际约束。每个候选记录入选、未达到主题/证据门槛、重复、等待后续处理、生成失败或审校未通过的原因；未处理项目进入后续候选池，原日期不变。不能把资源不足写成“没有新闻”。

无足够当天动态时，仍可提供重要背景、真实应用案例和独立学习内容；若这些也没有通过核查，就明确缺少合格内容，不生成虚构新闻。

## 三分钟商业思考

独立于首条新闻与新闻时间窗口选题。讲解型解释一个商业机制及其适用边界；练习型从真实案例提出开放问题与必要事实，不固定二选一、不附标准答案。以最近成功投递的类型交替尝试，发送失败不推进轮换；这是可调整的实现默认值，不是用户确认的永久比例。

两类都需要有来源的材料、独立审校和已讲主题记录。禁止用重复的通用“试点还是等待”填空替代内容。未通过审校就明确本期缺省，不把未经审校的备用段落伪装成正式栏目。

## 每周案例

独立长篇围绕明确经营问题组织真实材料，交代背景、选择、机制、结果、局限与可迁移条件。科技与传统行业按实际成功投递记录交替，每篇完整分析并留思考题，不能让整篇只剩购买工具或技术参数判断。传统行业覆盖餐饮零售、消费品与食品饮料，材料来自官方经营披露与财报；保留既有审校、备用投递和回执验收。

## 必须验收的行为

1. 热门但尚未公开使用的产品可评估，正文不会把演示冒充实测；无关注或使用证据的纯公告不会自动入选。
2. 同一栏有超过四条合格内容时仍可保留，少量重点、其余短消息；短消息与长稿均被独立审校。
3. 多年前的重要材料能进入背景，原日期明确；未来日期、无日期、已刊旧内容不能借背景入口绕过规则。
4. 新闻不足时仍可独立产出有来源的商业思考；历史记录控制轮换与重复，发送失败不写成已经读过。
5. Jev、Muse相关原始来源进入发现/补漏入口；真实抓取失败有诊断，不能宣称不再漏报。
6. 从来源到渲染执行完整回放，验证预算停止保留已审稿件和未完成队列；云端验证必须报告是否用了真实模型、是否发送邮件。

## 已接入的实现

- 正式日报调用 editorial-engine 与 business-thinking，默认采用 v2，不需额外功能开关。旧样例/旧邮件回放保持兼容。
- 默认最多3条重点，其他为简讯；140份详情、120条筛选、40条成稿是可调资源保护，不是每日保证条数。超限及预算/时间不足记录原因，发现队列跨运行保留。
- TypeSafe 使用官方 sitemap；Vercel 排除分类页；Meta 新闻室、TechRadar一手体验和TechCrunch AI扩大模型之外的应用发现。无法核实日期的材料不写成新发布，仅有日期的旧材料显示日精度。新产品仍需关注或真实使用证据。
- 长期已刊历史与商业思考记录不设14天截断；迁移已保留的成功发送记录。早于现存记录的完整阅读历史无法追溯，不能声称绝无历史遗漏。
- 私有部署在 runtime-state 分支持久化明确列出的历史、回执和费用账本。源码、完整草稿、抓取正文与凭据不写入此快照。缓存过期后可恢复；同步失败会使工作流明确报错。
- 周案例审校受限修复一次，失败后换题；同一周备用运行跳过已经失败的相同材料。正式投递以SMTP 250记录验收，工作流成功或来源验证不等于邮件已送达。

本地验收已包含新版行为测试；部署与云端运行结果单独记录，不把模拟模型的回放当成真实模型成稿。
