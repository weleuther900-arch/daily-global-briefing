# 项目迁移与维护

本文用于在更换电脑、重新授权或继续维护时快速恢复项目上下文。它只记录公开可迁移的信息，不包含 API 密钥、邮箱密码、GitHub 登录缓存、Cloudflare 凭据或运行缓存。

## 两个仓库的职责

| 仓库 | 用途 | 可以提交的内容 |
| --- | --- | --- |
| [daily-global-briefing](https://github.com/weleuther900-arch/daily-global-briefing) | 公开源码与文档 | 通用代码、来源规则、测试、样例、公开部署说明 |
| [daily-global-briefing-private](https://github.com/weleuther900-arch/daily-global-briefing-private) | 个人正式运行 | 私有工作流、运行配置、私有部署说明、内部变更记录 |

公开仓库适合阅读、Fork 和二次开发；个人正式运行应使用私人仓库。任何密钥、个人邮箱、运行状态账本、抓取缓存、邮件产物和诊断产物都不能提交到公开仓库。

## 换电脑后的恢复流程

1. 安装 Node.js 20 或更高版本，以及 GitHub CLI。
2. 登录 GitHub：

   ```powershell
   gh auth login
   gh auth setup-git
   ```

3. 在固定工作根目录克隆两个仓库。私有部署必须位于公开仓库的 `.private/deployment/`，这样根目录的维护约定、文件监听和部署资料路径在换机后仍然一致：

   ```powershell
   $briefingRoot = 'E:\AI\daily-global-briefing'
   git clone https://github.com/weleuther900-arch/daily-global-briefing.git $briefingRoot
   New-Item -ItemType Directory -Force -Path (Join-Path $briefingRoot '.private') | Out-Null
   git clone https://github.com/weleuther900-arch/daily-global-briefing-private.git (Join-Path $briefingRoot '.private\deployment')
   ```

4. 核验两个远端并在对应目录执行本地验证：

   ```powershell
   git -C $briefingRoot remote -v
   git -C (Join-Path $briefingRoot '.private\deployment') remote -v
   Push-Location $briefingRoot
   npm test
   npm run build:sample
   Pop-Location
   Push-Location (Join-Path $briefingRoot '.private\deployment')
   npm test
   npm run build:sample
   Pop-Location
   ```

5. 私人仓库要在 GitHub `Settings → Secrets and variables → Actions` 重新配置 Secrets。凭据不会随仓库迁移，不能从旧电脑目录复制。

## 私人运行所需的 Secrets

- `DEEPSEEK_API_KEY`
- `GMAIL_APP_PASSWORD`
- `BRIEFING_SENDER_ADDRESS`
- `BRIEFING_RECIPIENT_ADDRESS`
- `ENABLE_EMAIL_SEND`
- `X_BEARER_TOKEN`（可选）

Cloudflare 调度器另需在 Cloudflare Secret 中配置 `GITHUB_DISPATCH_TOKEN`。新电脑只需要维护代码或查看 GitHub Actions 时，不需要把这些值保存到本地文件。

## 修改和发布原则

- 修改前先查看 `git status`、当前分支和远端地址。
- 修改后至少运行 `npm test`；涉及正文或样例时再运行 `npm run build:sample`。
- 私人运行代码先提交到 `daily-global-briefing-private`，确认工作流和发送门状态后，再把不含私人信息的通用修复同步到公开仓库。
- 不要提交 `.env`、`.dev.vars`、`.tools`、`.cache`、`state`、`output`、`.runtime`、`logs` 和 `.diagnostics` 中的运行文件。
- GitHub Actions 成功只表示工作流成功；真正发信仍以运行记录中的 `sent=true` 和 SMTP `250` 为准。

## 当前内容规则

每条日报事件应包含：已确认事实、核心判断、大白话讲解、相关影响、判断边界和后续验证证据。三分钟商业思考必须是独立的经营决策练习，包含角色、二选一行动和三个观察变量，不得只是新闻复述。

周日商业案例必须通过独立审校才发送；审校拒绝时应记录为受控停止，不发送不合格内容，也不把正常的内容质量拦截伪装成系统故障。
