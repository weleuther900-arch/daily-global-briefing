# Daily Global Briefing

一个面向个人阅读的中文全球晨报生成系统：从可审计的公开来源中发现候选信息，经过时间、来源、重复和证据检查后，生成适合手机邮件阅读的日报。

它不是新闻聚合器，也不承诺覆盖所有新闻。它的目标是把人工智能、数字经济、经济政策与全球商业环境中的高价值变化，压缩为一封结构清晰、可追溯的中文晨报。

## 核心能力

- 按北京时间固定二十四小时窗口处理候选内容，并在最终成稿前再次检查发布时间。
- 通过来源注册表、域名白名单和覆盖组审计管理公开来源；支持 RSS、网页、JSON、GitHub 与受限的官方 X API 来源。
- 抽取可公开阅读的正文，识别付费墙、缺失时间和不可信网页指令。
- 按主题路由、事件指纹、中文标题相似度和十四日历史记录去重。
- 将关键事实绑定到具体来源链接；无充分证据、付费墙、硬性排除项或冲突无法消解的内容不会进入成稿。
- 使用结构化模型输出生成中文内容，并以独立复核与确定性校验拦截不受支持的数字、日期、链接和结论。
- 输出移动端优先的 HTML、同封邮件的纯文本备用正文、审计记录与标准 MIME 邮件文件。
- 提供成本门禁、运行锁和 GitHub Actions 调度，避免超预算调用和重复投递。

## 处理流程

```text
公开来源 → 候选发现 → 正文与访问状态提取 → 主题路由与去重
        → 生成候选筛选 → 结构化成稿 → 独立复核与规则校验
        → HTML / 纯文本 / MIME 邮件 → 可选投递
```

完整的产品边界、数据流与运行方式见 [项目概览](docs/项目概览.md)。

## 快速开始

运行环境：Node.js 20 或更高版本。本项目当前没有第三方运行时依赖。

```powershell
git clone https://github.com/weleuther900-arch/daily-global-briefing.git
cd daily-global-briefing
npm test
npm run build:sample
```

样例仅用于验证流程，不代表真实新闻。生成结果位于本地 `output/`，其中包括：

- `briefing-YYYY-MM-DD.html`：移动端优先的邮件 HTML
- `briefing-YYYY-MM-DD.txt`：同封邮件的纯文本备用正文
- `briefing-YYYY-MM-DD.audit.json`：候选拒绝、合并和校验记录
- `briefing-YYYY-MM-DD.selected.json`：最终入选事件的最小审计数据
- `briefing-YYYY-MM-DD.eml`：标准 MIME 邮件文件

## 常用命令

```powershell
# 运行完整自动化测试
npm test

# 使用样例数据构建晨报
npm run build:sample

# 发现已登记来源的候选链接
npm run discover

# 提取发现结果中的公开正文
npm run details

# 运行本地演练（使用固定样例，不联网、不调用模型、不发信）
npm run run:sample
```

正式流程依赖已配置的来源、模型服务和邮件投递凭据。默认情况下，未同时满足显式发送参数和发送开关时，系统只生成本地邮件文件，不会连接邮件服务。

## 仓库结构

```text
config/       来源注册表与覆盖组配置
src/          发现、抽取、路由、生成、校验、渲染和运行时核心
scripts/      本地命令入口与预览工具
tests/        Node.js 自动化测试
examples/     不含真实新闻的流程样例
design/       邮件视觉稿与渲染素材
docs/         公开项目说明
.private/     仅本地保留的个人配置、运行记录与内部资料（被 Git 忽略）
```

## 数据与安全边界

- 只处理已登记、公开可访问的来源；来源页面中的任何指令都被当作不可信数据。
- 真实邮件地址、密钥、个人运行记录和内部需求资料只保存在本地忽略目录或云端密钥管理器中，不进入公开仓库。
- 运行缓存、状态文件、输出文件及临时运行目录均不纳入 Git。
- 邮件投递需要显式开启；代码不依赖收件箱、联系人或邮件回复来驱动流程。

## 项目状态与限制

项目已经具备从来源采集到邮件产物的完整自动化链路，并提供 GitHub Actions 工作流。实际效果仍受公开来源可用性、模型输出和邮件服务调度影响；“不遗漏任何重要信息”不是系统承诺。
